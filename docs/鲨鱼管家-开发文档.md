# 鲨鱼管家｜开发文档（评审稿 v0.1）

> 状态：待产品确认。本文件确认前，不创建业务代码、不接入第三方账号、不发布 GitHub 仓库。

## 1. 项目定义

| 项目 | 约定 |
| --- | --- |
| 产品名称 | 鲨鱼管家（Shark Butler） |
| 产品形态 | macOS、Windows、Linux 本地桌面应用 |
| 核心价值 | 在一个本地工作台集中管理已获授权的多个店铺账号、商品和订单 |
| 首期范围 | 账号管理、商品管理、订单管理、客服工作台 UI、系统设置 |
| 实现方式 | 独立的 Tauri 应用，不复制参考项目代码 |

### 1.1 参考边界

参考项目 `zhinianboke/xianyu-auto-reply` 提供了多账号、聊天、商品和订单等产品思路；其公开说明采用 FastAPI + React + MySQL + Redis + Playwright 的服务端架构，并标注 AGPL-3.0 许可。

鲨鱼管家将采用全新的 Tauri 本地优先架构与独立代码实现，只参考公开的功能分层和本次提供的界面布局。不得复制其源码、素材、品牌元素、私有接口调用方式或规避平台风控的实现。

## 2. 目标、范围与非目标

### 2.1 首期目标（MVP）

1. 支持创建、授权、启停、排序和查看多个店铺账号。
2. 按账号查看商品，支持搜索、筛选、编辑本地备注和批量上下架请求。
3. 按账号查看订单，支持状态筛选、订单详情、备注、导出和手动刷新。
4. 提供与截图一致的信息密度和“三栏客服工作台”视觉框架；聊天实时收发留作后续接入能力，不在 MVP 承诺自动化回复。
5. GitHub 推送标签后，自动生成 macOS、Windows、Linux 的可下载安装包并附到 Release。

### 2.2 明确不做（MVP）

- 未获平台书面授权的接口逆向、绕过登录、反检测、风控规避、批量骚扰或自动成交。
- 自动发货、自动评价、自动回复、采集/搬运、分销、支付和云端多用户协作。
- 账号密码明文保存，或上传 Cookie、会话令牌至非用户指定的服务器。

以上功能若后续确有需要，须单独确认平台规则、数据处理方式和产品需求后再纳入版本计划。

## 3. 用户与核心流程

| 角色 | 典型任务 |
| --- | --- |
| 店主/运营 | 添加和切换店铺、检查授权是否失效、管理商品、跟进订单 |
| 客服 | 在工作台筛选会话、查看关联商品及订单（接入能力完成后） |
| 管理员 | 配置数据目录、导出/导入本地数据、查看日志与应用更新 |

**主流程**：首次启动 → 设置本地数据目录 → 添加账号 → 在平台认可的授权页完成用户主动授权 → 同步商品/订单 → 在工作台筛选、处理、备注或导出数据。

当平台不提供可用的官方/书面授权接口时，应用应明确显示“仅本地资料管理，暂不可同步”，而不是尝试模拟或绕过平台行为。

### 4.2 截图到产品页面的映射

截图采用高效工作台布局，鲨鱼管家将保留其交互结构，但使用自有图标、文案和视觉资产：

| 截图区域 | 鲨鱼管家设计 |
| --- | --- |
| 最左侧窄栏 | 固定主导航：概览、客服、账号、商品、订单、设置 |

| 顶部状态区 | 同步状态、授权到期提醒、刷新、账号菜单 |

### 4.3 关键页面规格

#### A. 账号管理

- 卡片和表格两种视图；字段：头像、店铺名、平台、账号别名、授权状态、最近同步、商品数、订单数。
- 状态：未授权、授权有效、即将过期、授权失效、同步中、异常、已停用。
- 操作：添加、重新授权、立即同步、编辑别名/分组、查看日志、停用、移除本地数据。
- 授权仅通过平台允许的方式完成；秘密数据进入系统安全凭据库，本地数据库只保存引用和必要元数据。

#### B. 商品管理

- 表格字段：主图、标题、所属账号、价格、库存、上架状态、最后同步、商品 ID、本地标签。
- 筛选：账号、上架状态、库存、价格区间、标签、关键词和更新时间。
- 详情抽屉：图文、规格、库存、同步记录、关联订单、本地备注。
- 批量操作由权限与平台适配器决定；执行前弹出影响范围确认，并记录结果。

#### C. 订单管理

- 表格字段：订单号、商品、买家脱敏标识、账号、金额、订单状态、创建/付款/完成时间、售后状态、备注。
- 状态分组：待付款、待发货、运输中/待收货、已完成、退款/售后、已关闭（以实际平台枚举为准）。
- 详情：订单时间线、商品快照、金额明细、收件信息最小化展示、内部备注、同步日志。
- 支持 CSV 导出；导出前可选字段，默认屏蔽不必要的个人数据。

#### D. 客服工作台（UI 优先）

- 采用截图的“三栏 + 顶部标签”节奏：左侧列表、中部详情、右侧业务上下文。
- MVP 显示演示/本地会话数据和空状态；只有平台允许的消息接入完成后才启用消息同步与发送。
- 右栏标签：客服、快捷回复、商品、订单、客户。无能力时显示清晰的接入状态与下一步。

## 5. 品牌与 Logo 方向（待确认后出图）

### 5.1 品牌语气

专业、敏捷、可靠，不使用凶猛或攻击性的“鲨鱼”表达。核心意象是“守护店铺运营的智能管家”。

### 5.2 建议方案：`S` 形鲨鱼管家

- **图形**：将鲨鱼背鳍和流线尾部收束成一个简洁的 `S`，负空间包含小领结/领结切面，表达“管家”。
- **界面主色**：鲨鱼黄 `#FFD400`，辅以金黄 `#F4B400` 与深墨 `#25313A`；黄色用于背景、选中态和主操作。
- **鲨鱼图形**：保留原始深海蓝/电光青配色，使 Logo 在黄色背景上保持辨识度。
- **字标**：中文“鲨鱼管家”采用现代无衬线粗体；英文辅助名 `Shark Butler` 仅在关于页或国际化版本使用。
- **交付物**：SVG 源文件、浅/深色横版、方形 App 图标、单色版、Favicon/托盘图标以及最小使用规范。

> Logo 在本开发文档确认后生成。届时应以原创 SVG/位图资产交付，不挪用参考截图的品牌或图形。

## 6. 技术架构

### 6.1 技术选型

| 层 | 选型 | 原因 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | Rust 后端、体积小、三端桌面能力和安全权限模型 |
| 前端 | React + TypeScript + Vite | 成熟组件生态、迭代快、类型约束清晰 |
| UI | Tailwind CSS + shadcn/ui 风格基础组件 + Lucide 图标 | 可实现截图的高密度后台布局，同时保持可访问性 |
| 本地状态 | Zustand + TanStack Query | 轻量 UI 状态与可控的同步缓存 |
| Rust 业务层 | Tauri Commands + Tokio + Serde | 统一本地业务、异步任务、强类型数据边界 |
| 本地数据 | SQLite（SQLx migrations） | 离线可用、便于打包和备份；不依赖 MySQL/Redis 服务 |
| 敏感凭据 | 系统 Keychain/Credential Manager/libsecret，经 Tauri 安全插件封装 | 不将密码、令牌写入 SQLite、日志或前端存储 |
| 集成层 | `PlatformAdapter` Rust trait | 将授权、同步、商品/订单操作与 UI 解耦；优先官方 API |
| 日志/诊断 | tracing + 本地滚动日志 | 可诊断且能进行个人信息脱敏 |

### 6.2 模块边界

```text
React 工作台
  ├─ 页面与组件：概览 / 客服 / 账号 / 商品 / 订单 / 设置
  ├─ 数据访问：Tauri invoke + 事件订阅
  └─ 本地展示缓存
        │
Tauri / Rust Core
  ├─ AccountService / ProductService / OrderService
  ├─ SyncScheduler（显式启动、可暂停、退避重试）
  ├─ PlatformAdapter（官方 API / 已授权连接器）
  ├─ SQLite Repository + migration
  ├─ SecretStore（系统安全凭据库）
  └─ Audit & Diagnostics
        │
平台官方或书面授权的接口
```

### 6.3 同步与错误处理

- 用户可手动刷新；自动同步默认关闭，启用时可按账号配置间隔并限制并发。
- 每次同步产生任务记录：开始/结束、对象数量、成功/失败、可读错误、可重试标记。
- 采用增量游标与幂等 upsert；网络错误指数退避，不静默重试危险的写操作。
- UI 展示“最后成功同步时间”和数据来源；本地缓存不可代替平台真实状态。

## 7. 本地数据模型（初版）

| 实体 | 关键字段 |
| --- | --- |
| `accounts` | id、platform、display_name、alias、group、status、last_sync_at、created_at |
| `account_credentials` | account_id、credential_ref、expires_at、updated_at（无明文秘密） |
| `products` | id、account_id、platform_product_id、title、price、stock、status、cover_url、tags、synced_at |
| `orders` | id、account_id、platform_order_id、status、amount、buyer_masked_name、created_at、paid_at、completed_at、synced_at |
| `order_items` | order_id、product_id、title_snapshot、quantity、unit_price |
| `notes` | id、entity_type、entity_id、content、created_at、updated_at |
| `sync_jobs` | id、account_id、resource、trigger、status、cursor、started_at、finished_at、error_code |
| `audit_logs` | id、actor、action、target_type、target_id、result、occurred_at |

个人数据保留本地且最小化。删除账号时提供三个明确选项：仅停用、移除凭据、移除凭据及该账号本地业务数据；后两项均需二次确认。

## 8. 安全、合规与隐私验收

1. 不记录账号密码、会话令牌、完整收件地址、手机号或支付信息到前端存储和普通日志。
2. 生产构建关闭开发者工具、限制 Tauri capability、严格校验命令参数和外部 URL。
3. 所有导出动作由用户发起；预览中脱敏，导出文件显示敏感数据提示。
4. 提供“导出本地数据”和“清除本地数据”入口，并明确保存位置。
5. 发布前做依赖许可证清单、Rust/Node 漏洞扫描和安装包签名校验。
6. 平台接入必须获得对应接口权限并遵守其服务条款；无法合规接入时，仅交付本地管理体验和适配器占位实现。

## 10. 交付阶段与验收标准

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| P0：产品确认 | 本文档、信息架构、Logo 方向确认 | 用户确认范围、平台、视觉方向、是否启用客服能力 |

## 11. 测试策略

- 前端：组件、状态与页面流程测试；关键表格筛选和空/错/加载状态覆盖。
- Rust：服务、仓储、凭据边界、同步幂等与错误映射单元测试。
- 集成：使用模拟 `PlatformAdapter`，不在 CI 使用真实账号或凭据。
- E2E：首次启动、添加账号、商品/订单筛选、导出、删除数据确认、离线提示。
- 发布验收：macOS/Windows/Linux 虚拟机或 Runner 上安装启动、版本号和签名状态检查。
